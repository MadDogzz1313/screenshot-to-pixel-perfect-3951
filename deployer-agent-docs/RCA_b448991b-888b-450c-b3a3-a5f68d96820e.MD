# RCA — Glocke im Karten-Menü öffnet Profil statt Benachrichtigungen

## Symptom
Tippen auf die Glocke oben rechts auf dem Karten-Screen navigiert nur zum Profil und öffnet NICHT die Benachrichtigungsübersicht. Identisch in Preview und Production (beide fahren denselben Build/Quellcode), daher ein reiner Source-Bug — kein Infra-/Pipeline-/Secret-Problem. Deployment ist live und gesund (Run `b448991b-888b-450c-b3a3-a5f68d96820e`, Status success).

## Root Cause (bewiesen durch Quellcode im eph-Sandbox)
Datei: `src/routes/karte.tsx`

- Zeile 28: `const bellTo = user?.isAdmin ? "/admin" : "/profil";`
- Zeile 43-46:
  ```tsx
  <Link to={bellTo} aria-label={...} data-testid="map-bell-button" className={`${roundBtn} mt-3`}>
    <Bell className="h-6 w-6" />
    {pending > 0 && <span data-testid="map-bell-dot" .../>}
  </Link>
  ```

Die Glocke auf dem Karten-Screen ist ein reiner `<Link>` nach `/profil` (für Nicht-Admins). Sie verwendet NICHT die `NotificationBell`-Komponente und übergibt keinen Query-Parameter, der die Übersicht öffnet. Ergebnis: man landet auf der Profilseite, die Benachrichtigungen bleiben zu.

## Vorhandener Öffnen-Mechanismus (bereits im Code, ungenutzt)
Die Übersicht wird von `src/components/social/NotificationBell.tsx` als Sheet gesteuert (`open`-State, `onClick={() => setOpen(true)}`). Diese Komponente besitzt bereits einen Deep-Link:
```ts
useEffect(() => {
  const url = new URL(window.location.href);
  if (url.searchParams.get("glocke") === "1") { setOpen(true); url.searchParams.delete("glocke"); window.history.replaceState(...); }
}, []);
```
D. h. der Aufruf `/profil?glocke=1` öffnet die Benachrichtigungsübersicht automatisch. Die Profilseite rendert `NotificationBell` bereits im Header (`src/routes/profil.tsx` Zeile 53: `headerRight={<NotificationBell />}`), also greift der Trigger dort.

## Empfohlener Fix (Code — durch E1)
In `src/routes/karte.tsx` den Bell-Link so ändern, dass er für Nicht-Admins den vorhandenen Deep-Link `glocke=1` mitgibt, damit die Übersicht direkt aufgeht. Minimal, keine weiteren Navigations- oder Datenänderungen:

```tsx
// Nicht-Admin: direkt die Benachrichtigungen öffnen statt nur zum Profil zu navigieren
<Link
  to={bellTo}
  search={user?.isAdmin ? undefined : { glocke: "1" }}
  aria-label={pending ? tr("{0} wartende Beiträge", pending) : tr("Hinweise")}
  data-testid="map-bell-button"
  className={`${roundBtn} mt-3`}
>
```

Hinweis zur Route-Typisierung: TanStack Router kann für `/profil` eine `validateSearch`/Search-Schema-Definition erwarten. Falls der TypeScript-Build den `search`-Param ablehnt, in `src/routes/profil.tsx` ein `validateSearch` ergänzen, das `glocke?: "1"` akzeptiert (die `NotificationBell`-useEffect liest den Param ohnehin aus `window.location`). Admin-Zweig (`/admin`) bleibt unverändert.

## Validierung
- Quellcode statisch verifiziert im eph-Sandbox (Run b448991b): `bellTo`-Logik und `<Link>` in `karte.tsx`; `NotificationBell`-Deep-Link in `NotificationBell.tsx`; `NotificationBell` im Header von `profil.tsx`.
- Keine Live-Reproduktion über die URL möglich (keine Zugangsdaten; Glocke nur für eingeloggte Nutzer sichtbar). Der Bug ist aber rein statische Routing-Logik und damit eindeutig.
- Nach dem Code-Fix ist ein Redeploy nötig, damit die Änderung in Production greift.

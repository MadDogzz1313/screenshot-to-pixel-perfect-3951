# RCA — Map "Fullscreen" button does nothing (Production = Preview)

## Problem statement
User reports in BOTH Preview and Production: the fullscreen button on the right side of
the map does not open the map in fullscreen. Expected: tapping `data-testid="map-fullscreen-button"`
(or the visible fullscreen button) should display the map filling the map area/view; no change
to markers, zoom/pan logic or other map behavior.
Production URL: https://leonida-preview-2.emergent.host

## What I did
- `describe_deployment_state`: deployment `leonida-preview-2`, active run `b448991b-888b-450c-b3a3-a5f68d96820e`,
  status **success**, kubernetes frontend, tier_0. The app is healthy and live — this is NOT a
  deploy/infra problem.
- Spawned an eph sandbox on the active run's source and read the map component verbatim.

## Root cause (proven in source, not inferred)
The fullscreen feature is **not implemented in the source**. In `src/components/MapCanvas.tsx`:

1. There is **no** element with `data-testid="map-fullscreen-button"` anywhere in the repo
   (grep across all `.ts/.tsx/.js/.jsx` returned nothing).
2. There is **no** Fullscreen API call anywhere (`requestFullscreen` / `webkitRequestFullscreen`
   — no matches), and no CSS/state that expands the map container to fill the viewport.
3. The button the user is tapping is the **Maximize-icon** button, which in the floating map
   variant is actually:
   ```tsx
   <button ... data-testid="map-locate-button" onClick={resetView} className={CTRL}>
     <Maximize className="h-5 w-5" />
   </button>
   ```
   Its handler only recenters/fits the map:
   ```tsx
   const resetView = () => zoomRef.current?.centerView(1, 250);
   ```
   `aria-label` = "Ganze Karte anzeigen" ("show whole map"). It resets zoom/pan — it does **not**
   enter fullscreen.

Because this is entirely a source-code matter and Production is built from exactly this source,
the symptom is identical in Preview and Production. The Maximize icon makes it *look* like a
fullscreen control, but no fullscreen logic was ever wired up, and the expected test id does not exist.

## Evidence
- `grep -rl 'map-fullscreen-button' src` → no match
- `grep -ri 'fullscreen|FullScreen|full-screen' src` → no match in source
- `grep -o 'requestFullscreen|webkitRequestFullscreen'` in built bundle → no match
- `src/components/MapCanvas.tsx` buttons present (floating variant): `map-layers-button`,
  `map-locate-button` (Maximize → resetView), `map-zoom-in-button`, `map-zoom-out-button`.
  No fullscreen button.

Note: static code analysis is conclusive; I did not click the button in a live browser (no
browser in the sandbox), but the absence of both the test id and any fullscreen handler fully
explains the symptom.

## Suggested fix (Code — E1)
Implement the fullscreen control in `src/components/MapCanvas.tsx`:
- Add a dedicated button with `data-testid="map-fullscreen-button"` (keep the existing
  `map-locate-button` as the "fit/recenter" control, or repurpose deliberately — but the expected
  test id must exist).
- Wire an `onClick` that toggles fullscreen of the map container, e.g. call
  `element.requestFullscreen()` on the map wrapper (`data-testid="map-floating"` /
  `data-testid="map-content"` container) and `document.exitFullscreen()` to leave, OR a CSS-based
  "fill the viewport/map area" expansion if a true browser fullscreen is not desired (the request
  says "fill the map area/view").
- Do not alter markers, zoom/pan logic or other map functions, per the requirement.

Redeploy after the code change to ship it to Production.

# RCA — initial deploy failed at pull_source; template↔project-type mismatch

**Deployment:** leonida-preview-2 (f023b72d-2703-4461-880d-04d3a7470063)
**Run:** 1ba20357-f6e8-411f-870e-691293e8c1c5 (initial, arm64, tier_0, frontend_type=kubernetes)
**Template:** farm_ts_react_mongo_base_image
**Failing step:** pull_source
**Error:** `prepare build context: update python dependencies: write requirements.txt: open .../app/backend/requirements.txt: no such file or directory`

## Root cause
The app is a **TanStack Start (Vite 8 + nitro, SSR + a server function) Lovable project at repo root**, data in external Supabase, no Mongo. The target template `farm_ts_react_mongo_base_image` is a **FastAPI + static-React-SPA + Mongo** image with a rigid layout contract. The two are incompatible on multiple independent points; `pull_source` is just the first wall.

## Template contract (read from the manifest set — Dockerfile, Dockerfile.cloudbuild, config.yaml, nginx.conf, entrypoint.sh)

1. **Source copy**: filesystem copy of preview pod `/app` (excludes `node_modules`, `.git`), not git. A `pull_source` sub-step pins Python deps and requires `backend/requirements.txt` to exist → this is the observed failure. The copy implementation is platform-internal (NOT in the readable manifest set), so exact symlink-follow behavior is UNVERIFIED — but the recursive self-symlink `/app/frontend -> /app` is a real hazard and must be replaced with a real `frontend/` directory.

2. **Frontend build**: stage `frontend-build` does `COPY frontend/ /app/`, sed-rewrites preview URL in `/app/.env`, then `yarn install --prefer-offline --check-files --network-timeout 100000 && yarn build`. Output must be **`build/` (CRA) or `dist/` (Vite)**; neither → `ERROR: No build or dist directory found` → exit 1. Nitro outputs `.output/` → would fail here.
   **Serve**: static files only, nginx from `/usr/share/nginx/html`, **listen 8080**, SPA fallback `try_files $uri /index.html`. **No node process** (no yarn start/preview, no `node .output/server/index.mjs`) → SSR and the server function would NEVER run.

3. **Backend**: uvicorn on `:8001` (command parsed from supervisor `[program:backend]`, `--reload` stripped, dir `/app/backend`). Requires `backend/server.py` + `backend/requirements.txt`. Health: nginx `GET /health` proxies to 127.0.0.1:8001 (4xx=healthy, 5xx=unhealthy). Routing: `/api` → backend (WS upgrade supported), everything else → static SPA.

4. **Mongo to start**: `MONGO_URL` is a SYSTEM secret, always injected; `provision_mongo` always runs on initial deploy. The template/entrypoint do NOT require Mongo — only uvicorn is launched. Crash-on-no-Mongo depends solely on `server.py`. A backend that answers `/health` and `/` is still required for health_check.

5. **Frontend BUILD-time env**: only `frontend/.env` is copied into the build and baked in; a repo-root `/app/.env` is NOT. Secrets-tab values are NOT present at build time (runtime-only). `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` must be committed into `frontend/.env` to appear in the bundle. Template's only env transform: sed preview-URL → prod BACKEND_URL + `ENV FRONTEND_ENV=REACT_APP_BACKEND_URL=...` (CRA-style).

## Why it cannot be fixed by a manifest edit
This is not build plumbing — it's a template/application-model mismatch. The farm template is architecturally static-SPA + FastAPI; it has no mechanism to run a long-lived SSR node server. Making it work means either abandoning SSR or choosing a different template.

## Recommended paths (for E1 + user decision)
- **Option A — conform to farm (drops SSR):** split the project into `frontend/` (a pure client SPA that builds to `dist/`, with Supabase keys in `frontend/.env`) and `backend/` (FastAPI `server.py` + `requirements.txt` answering `/health`, exposing logic under `/api`). The TanStack server function must be reimplemented as a FastAPI `/api/*` route. No SSR; remove the `frontend -> /app` symlink.
- **Option B — use a template that runs a Node SSR server** (long-lived `node .output/server/index.mjs` on a fixed port with a health path). farm_ts_react_mongo_base_image is not that template. This is the natural fit for TanStack Start SSR + server functions + external Supabase (Mongo unused).

Recommend Option B if SSR/server functions are required.

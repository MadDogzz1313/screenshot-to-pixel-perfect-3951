# RCA — Gäste können Fundort-Detailansicht öffnen (Karten-/Spot-Click-Flow)

Deployment: `leonida-preview-2` · URL: https://leonida-preview-2.emergent.host
Active run: `b448991b-888b-450c-b3a3-a5f68d96820e` (status: success — Produktion ist gesund, kein Deploy-/Infra-Fehler)
Analyse: Quellcode aus dem aktiven Run in isoliertem eph-Sandbox gelesen (statische Code-Analyse, kein Laufzeit-Test, da keine Zugangsdaten).

## Erwartetes vs. aktuelles Verhalten
- **Erwartet:** Nicht angemeldete Nutzer (Gäste) sehen Karte + Pins, aber beim Antippen eines Pins **keine** Detailansicht — stattdessen ein Anmelde-/Registrierungs-Hinweis mit Link zum Login. Angemeldete Nutzer: Detailansicht unverändert.
- **Aktuell:** Gäste können die vollständige Detailansicht öffnen. Es existiert **kein** Auth-Gate auf dem Pin→Detail-Übergang.

## Der aktuelle Click-Flow (nachvollzogen)
1. `src/components/MapCanvas.tsx` — jeder Pin ist ein `<button onClick={(e) => { e.stopPropagation(); onSelect?.(s); }}>`.
2. `src/routes/karte.tsx` — `<MapCanvas ... onSelect={setSel} />`. Der Klick setzt `sel` (unabhängig vom Auth-Status). Bei gesetztem `sel` wird eine Overlay-Karte `<SpotCard spot={sel} />` gerendert.
3. `src/components/SpotCard.tsx` — die SpotCard ist selbst ein `<Link to="/fundort/$id" params={{ id: spot.id }}>`. Ein Tippen navigiert direkt zur Detail-Route.
4. `src/routes/fundort.$id.tsx` — die Detailseite.

## Root Cause (belegt im Code)
Es gibt an keiner Stelle einen Auth-Check für das Öffnen der Detailansicht. Entscheidend ist `src/routes/fundort.$id.tsx`:

```
const access = useSpotAccess(id, !!user); ...
if (user && access.data === false) return <... Freischalt-Panel ...>;   // nur wenn eingeloggt
if (user && access.isPending)       return <... Lade-Status ...>;        // nur wenn eingeloggt
// -> fällt sonst durch zur VOLLSTÄNDIGEN Detailansicht
```

Beide Guard-Zweige sind an `user` (truthy) gekoppelt. Für einen Gast ist `user === null` (Store: `user: AppUser | null`, plus eigenes `guest`-Flag via `continueAsGuest()` von der Login-Seite „Ohne Anmeldung zur Karte"). Dadurch werden **beide** Guards übersprungen und die Komponente rendert die komplette Detailansicht.

Zusätzlich:
- In `karte.tsx` feuert der Pin-Klick (`onSelect={setSel}` → SpotCard-`<Link>`) identisch für Gäste und eingeloggte Nutzer — keine Verzweigung nach Auth-Status.
- `src/routes/__root.tsx` enthält **keinen** `beforeLoad`/Redirect-Guard (grep ohne Treffer), d. h. auch ein direkter Deeplink auf `/fundort/$id` ist für Gäste offen.
- `need()` in `fundort.$id.tsx` gated nur Aktionen (Like/Merken/Korrektur) mit Toast „Bitte anmelden" — **nicht** das Ansehen.

Das Anzeigen der Karte und Pins für Gäste funktioniert bereits wie gewünscht (Pins werden aus `spots` gerendert, unabhängig vom Login).

## Empfohlener Fix (Code — für E1; kein Deploy-/Secret-/Infra-Problem)
Am besten an **beiden** Stellen absichern, damit UX und Deeplink abgedeckt sind. Angemeldetes Verhalten (inkl. Coins-/Freischalt-Logik) bleibt unverändert.

1. **Pin-Klick in `src/routes/karte.tsx` (UX):** Bei Gast (`!user`) statt `setSel(s)` einen Anmelde-/Registrierungs-Hinweis anzeigen — z. B. ein Overlay-Panel (Stil analog zum vorhandenen `spot-locked-panel`) oder Toast mit einem `<Link to="/">` zur Login-/Registrierungsseite. Alternativ SpotCard für Gäste nicht navigieren lassen und den Hinweis einblenden.
2. **Route-Guard in `src/routes/fundort.$id.tsx` (Deeplink):** Früh im `Detail()` prüfen: `if (authReady && !user) return <Login-Hinweis-Panel mit <Link to="/">>;`. `authReady` (im Store vorhanden) berücksichtigen, damit der Hinweis nicht kurz aufblitzt, bevor die Session geladen ist. Alternativ ein `beforeLoad`-Redirect auf `/`.

Beide Dateien: `src/routes/karte.tsx`, `src/routes/fundort.$id.tsx` (ggf. `src/routes/__root.tsx` für globalen Guard).
